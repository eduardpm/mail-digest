# Mail Digest

A private, read-only Proton Mail technology-news dashboard. At 05:00 Europe/Brussels it fetches the previous calendar day's messages from a configured Bridge folder, starts a local Ollama server when needed, distills the newsletters into a daily tech briefing, saves summaries to SQLite, unloads the model, and stops Ollama if it started it. The landing page is a monthly calendar and every completed day has its own detail URL.

The web server listens only on `127.0.0.1:8765`. Cloudflare Tunnel should publish that address, with Cloudflare Access protecting the public hostname. Do not publish Ollama (`11434`) or Proton Bridge (`1143`).

## Privacy and behavior

- IMAP is opened read-only and messages are fetched with `BODY.PEEK[]`, so they are not marked as read.
- Raw message bodies and attachments are not saved. SQLite contains sender/subject metadata, generated summaries, categories, and filtered HTTP(S) article links extracted from the newsletters.
- Email content is treated as untrusted input. The agent has no tools and cannot send, move, or delete mail.
- The scheduler catches up if the server starts after 05:00, retries failures after 30 minutes, and retries a job left stale by a crash after three hours.
- A long day is summarized in batches before the final digest to stay within a small local model's context.

## Prerequisites

1. Install and sign in to Proton Mail Bridge. Copy the IMAP username, generated password, port, and security mode shown by Bridge. The generated password is not your Proton account password.
2. Install Ollama and download the model once:

   ```bash
   ollama pull qwen3:4b
   ```

The application itself uses only Python's standard library and needs no Python packages.

## Configure

```bash
cp config.example /home/epalk/.config/mail-digest.env
chmod 600 /home/epalk/.config/mail-digest.env
```

Edit `/home/epalk/.config/mail-digest.env` and enter the credentials generated by Proton Mail Bridge. Keep the file private.

Check the read-only Bridge login, mailbox access, model startup, and model installation:

```bash
PYTHONPATH=src python3 -m maildigest --env-file /home/epalk/.config/mail-digest.env check
```

Create a digest manually (useful for the first test):

```bash
PYTHONPATH=src python3 -m maildigest --env-file /home/epalk/.config/mail-digest.env run --date 2026-08-12
```

Run the server in the foreground:

```bash
PYTHONPATH=src python3 -m maildigest --env-file /home/epalk/.config/mail-digest.env serve
```

Then open `http://127.0.0.1:8765/`. The health endpoint is `/healthz`.

## Run continuously with systemd

After the foreground test succeeds:

```bash
mkdir -p /home/epalk/.config/systemd/user
cp ops/mail-digest.service /home/epalk/.config/systemd/user/mail-digest.service
systemctl --user daemon-reload
systemctl --user enable --now mail-digest.service
systemctl --user status mail-digest.service
```

Follow logs with:

```bash
journalctl --user -u mail-digest.service -f
```

If the service should run while the user is logged out, enable user lingering once with `loginctl enable-linger epalk` (this may require administrator approval).

## Commands

- `serve`: dashboard plus scheduler
- `run [--date YYYY-MM-DD]`: manually process a day; defaults to yesterday
- `check`: validate secrets and verify that Ollama can start
